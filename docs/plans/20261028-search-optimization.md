# 2026-10-28 采价搜索优化与复查

## 用户目标与边界

尽量由系统取得正确的型号＋存储报价，减少人工二次核验。颜色不限；继续限制原先确认的 14 家品牌京东自营店。型号、容量、特殊版本及券额真实矛盾仍须保留校验。不得为了消除待核验数反推券额、把未知券额改为零或采纳其他容量。

本轮仅更新本地预览 `http://localhost:8001`，未部署云端。原始云端数据库未改动。

## 已修复的遗漏

- 数字型号与 RAM 连读：`一加15 16GB`、`vivo X500 12GB` 原来去空格后把型号数字算进内存。容量解析现在保留数字边界。
- 容量与网络连读：`16+512 5G手机` 不能解析为 5125GB。
- 处理器与 RAM 连读：`麒麟9030 12GB+512GB` 不能解析为 903012GB RAM。
- `G/GB`、`T/TB` 及省略单位的 `12+256` 使用相同的容量比较；支持 NFKC 全角加号和加号两侧空格。
- 只有 ROM 的 SKU（如畅享90 128GB）按标注的容量匹配；对于明确要求 12GB RAM 的 SKU，不因为候选标题只写 256GB 就猜出运行内存。
- `高定款/高定版`、`S26 Plus/S26+` 统一；徕卡影像营销词不再直接当成型号后缀。徕卡版等明确版本仍与普通版区分。
- 型号以主标题优先：Note17 Pro 标题尾部的“note15pro新款”不能被当作 Note15 Pro。历史发现的两条误自动生效记录已追加撤销版本，保留原证据。

## 搜索和选价

1. 品牌＋型号＋规范完整容量、简写容量、单独 ROM 多种写法。
2. 品牌＋型号、不含空格的型号、中英文品牌别名。
3. 去品牌型号、去版本词与系列词兜底；不使用纯数字（如 `15`）作为搜索词。
4. 以上重要型号词按页码 2–5 继续搜索，保留带品牌型号分页，避免只翻“15”等泛词。
5. 同一查询批次最多并行四个不同型号，每个型号内连续处理存储版本，相同搜索共享短时缓存；详情与链接在批次内共享缓存，失败会清除缓存。缓存保留原接口取得时间，不冒充新的查询时间。优先按接口稳定标识 `jdGoodsIdB` 联合标题、店铺与价格去重；缺少稳定标识时退回原 goodsId。避免变化的加密 goodsId 重复消耗详情名额，同时保留不同版本和价格变化的候选。每个 SKU 最多核对 24 个不同候选详情，每页最多 8 个。
6. 找到能通过价格交叉校验的同规格商品后停止；只有价券矛盾的候选时继续找其他颜色或链接。选择顺序优先完整且校验通过，其次比较挂牌减券的价格，不让异常偏低的 `actualPrice` 抢占结果。
7. 某个候选的详情失败，继续查询其他候选；如果最终无可用结果且存在详情请求失败，按接口失败重试，不冒充“未匹配”。
8. 商品身份已匹配但一个价格字段缺失时，保留其他已知字段，未知字段为空；发布仍经 `validateQuote` 校验。

所有搜索词、页码、候选排除理由、详情结果及请求失败继续写入审计日志。未匹配的新记录显示检索次数、详情数量和主要排除理由，不再只有一句笼统提示。

# 来源与变更历史性能优化

用户标注：REDMI Turbo 5 Max / 12G+256G，2026-10-28 的来源与变更历史。

## 原因

历史接口原先 SELECT * 并解析、返回所有原始 API 响应。抽屉即使折叠记录，也在每次 React 渲染中对全部原始响应执行 JSON.stringify，创建大段隐藏 DOM。历史加载又依赖整个价格 payload，后台刷新价格会不断重新下载和格式化同一历史。

## 处理

- 历史接口只返回报价摘要和生效版本，默认每页 30 条；增加按 SKU/日期的历史索引。
- 原始响应单独按记录加载，默认每段 12000 字符、服务端硬上限 16000。保留分页和完整下载，完整下载直接返回已保存的原文，不做大 JSON 解析/重排。
- 折叠时不创建原始响应 DOM。按原始记录拆分 memo 组件，各组件最多缓存 4 个片段。
- 用户点击时立即发起请求；局部结果同步提交，避免等待延后 effect/渲染任务。所有渲染文本有界。
- 历史只随选中 SKU、日期、记录版本或历史页码更新，不依赖整个价格表；增加短时摘要缓存。
- 同一 SKU 有新历史时更新摘要，不先清空已有历史组件，避免展开内容被重置。

## 本地实测

通过实际 localhost:8001 代理与 ego-browser 验证，不改动价格数据。

| 项目 | 结果 |
| --- | --- |
| 历史响应体 | 386287 → 3425 字节，减少约 99.1% |
| 历史接口 12 次请求中位数 | 1.66 ms |
| 历史接口上述请求最大值（含首次连接） | 34.15 ms |
| 分段接口示例 | 1.53 ms |
| 3 条日志首次点击到内容 DOM 就绪 | 9.7 / 5.0 / 6.5 ms |
| 3 条日志缓存重开到内容 DOM 就绪 | 0.4 / 0.8 / 0.6 ms |
| 后台刷新 6 秒期间新增历史请求 | 0 |
| 返回已缓存片段新增请求 | 0 |

DOM 就绪耗时与显示器绘制帧率区分记录；页面此前偶发的延后任务通过点击直接请求和局部同步提交处理。大日志只渲染当前片段，未删减证据。

完整响应下载与数据库原文逐字一致。49 项测试通过，包含 200 万中文字符的大响应不进入历史列表、分页限长、跨 SKU/日期访问隔离、完整下载。类型检查、构建和 diff 检查通过。

本地预览后端已在空闲时更新，没有中断采价任务。此版本仅本地 8001 生效。

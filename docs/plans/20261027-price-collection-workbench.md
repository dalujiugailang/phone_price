## 二、页面与日常工作方式

原始数据内部设置四个子 tab：

1. **每日采价**：选择单个日期，固定一行一个 SKU；身份列仅型号、存储版本。业务列为挂牌价、优惠券、国补后；辅助列为核验状态、商品链接、搜索链接、最后操作人和时间。actualPrice、价差、原始响应与候选商品放在详情抽屉；异常时在当前行展开关键差值。支持按未匹配、券价异常、待人工确认、我的任务筛选，批量粘贴价格。默认展示当天，不横向铺开所有日期。
2. **型号维度**：型号级维护品牌、机型定位、代际；同型号不同容量共享配置。补充系列、发布日期/代际基准日期作为可选字段。新型号缺失机型定位时留空并标“待配置”，不能猜测填入已有类别。
3. **核验队列**：在每日采价相同行数据上提供待办视图，不复制一份价格；可领取、打开商品/搜索链接、填写证据、修正挂牌或券额、确认在售/无货/停售。查询异常与业务停售分开处理。
4. **任务与日志**：每日任务进度、成功/异常/失败、重试情况、接口与人工操作记录。单个 SKU 可追溯历次候选、价格修订、发布和撤销。

PPV 与发售价保留在 SKU 详细配置；BI 出货价保留独立来源和已有匹配逻辑，放在详情或风险页，采价人员无需日常维护。新增 SKU 没有可靠 PPV 时不猜测、不复制其他容量的 PPV。

## 三、数据模型与关系

SQLite 继续承担在线事务与日志，DuckDB 继续承担派生分析。对 2–3 名用户先采用 SQLite WAL、短事务、busy timeout、服务端写入队列与备份即可；不以更换数据库作为前置条件。分析库只从已生效价格同步，不能反向覆盖在线编辑。

| 数据对象 | 粒度与约束 | 主要内容 |
| --- | --- | --- |
| 型号 models | 稳定 model_id；规范型号唯一 | 标准名称、品牌、机型定位、代际配置、启停 |
| 型号维度版本 model_dimension_versions | model_id + 生效时间/版本 | 旧值、新值、修改者、代际基准与生效日期 |
| SKU skus | 稳定 sku_id；model_id + RAM + ROM + 特殊规格标识唯一 | 原始/标准存储版本、原有 row_id、PPV、发售价、监控启停、首次纳入日期 |
| 别名 aliases | 来源 + 别名 + 规格上下文 | 标准型号映射、审批者、启用日期；禁止模糊别名自动合并 |
| 来源匹配 source_bindings | sku_id + provider + 来源配置 | 已核验 goodsId、商品链接、店铺、选品策略、颜色、绑定版本；失效时保留旧记录 |
| 采价任务 collection_runs / items | run_id；run_id + sku_id 唯一 | 目标业务日期、关键词、请求状态、任务租约、重试次数、成功/失败原因 |
| 原始报价 quote_observations | 每次请求/候选一个记录，不可覆盖 | 原始 JSON、接口版本、获取时间、goodsId、店铺、标题、链接、全部价格与券字段 |
| 每日工作记录 daily_price_work | sku_id + 业务日期唯一 | 引用 observation、人工覆盖值、字段版本、校验问题、核验状态、待发布值 |
| 生效价格版本 price_revisions | sku_id + 业务日期 + revision 唯一 | 生效挂牌/券额/公式值、来源、公式版本、证据、发布者/时间、撤销关系 |
| 核验问题 review_issues | 每个异常事件独立 ID | 原因码、影响字段、领取人、结论、证据、解决时间；一条报价可有多个问题 |
| 审计事件 audit_events | 追加写入 | 操作人、请求 ID、前后值、实体、版本、原因、时间；与写入事务一起提交 |

关系：型号 → 多个 SKU → 多日工作记录；一次工作记录可以引用多个原始候选和多个价格版本；核验问题关联到该日/该 SKU/该次报价；所有变更关联操作人与审计事件。查询用标准字段，原始 JSON 留作证据。

日期存完整 `YYYY-MM-DD`，业务时区用 Asia/Shanghai，抓取时间和审计时间存 UTC；页面可继续简写为 10.27，避免跨年日期相撞。金额用整数分，展示两位小数；不得解析不了就回填 0。

## 五、接口规范化与价格公式

已查阅当前买手脚本，搜索与详情是两个不同请求。现有搜索入口为 `https://appapi.maishou88.com/api/v1/homepage/searchList`，详情入口为 `https://appapi.maishou88.com/api/v3/goods/detail`；接口鉴权留在服务端，页面不暴露令牌。实现时复用当前调用协议并验证云端运行环境的凭证、可达性、额度和超时行为，不把本机脚本可用当成云端可用。

| 原始字段/导入列 | 系统字段 | 处理规则 |
| --- | --- | --- |
| originalPrice / 1027挂牌价（元） | list_price | 挂牌原值，保留来源；不使用 actualPrice 替代 |
| couponPrice / 1027接口券额（元） | api_coupon_amount → coupon | 保留 API 原券额；人工修正写 override，不覆盖原始响应 |
| actualPrice / 1027参考到手价（元） | api_actual_price | 原始参考价，仅展示和校验；不直接用作国补后 |
| list_price - coupon | net_before_subsidy | 内部公式值，不冒称接口 actualPrice |
| 用户国补公式 | final_price | 服务端统一计算，只读；挂牌/券额变化后即时重算 |
| shopName、shopType、tagList、sourceType | 来源核验字段 | 店铺全名白名单、京东、自营依据同时校验 |
| 商品标题、规格、goodsId、购买链接 | 来源与匹配证据 | 保存完整标题、所有候选、商品标识与原始链接 |
| couponConditions、开始/结束时间 | 券条件 | 缺失与明确 0 分开；未知门槛/期限显示未确认 |

用户公式（不改成其他补贴政策）：

```text
净价 = 挂牌价 - 优惠券
国补后 = IF(净价 > 6000, 净价 - 500, 净价 - MIN(净价 * 15%, 500))
```

严格大于 6000，等于 6000 走第二分支。使用十进制定点或整数分实现；金额最终按分四舍五入，存储 `formula_version=user_subsidy_v1`。Excel 导出使用对应行真实单元格引用和相同公式，不能写死 FL4/FM4。缺挂牌、缺券额、负数或券额大于挂牌均不计算；明确返回 0 元券可参加计算，但若 actualPrice 不一致仍阻止自动生效。国补后展示“按业务公式测算”，不承诺结算页可享受政策。

例：挂牌 3000、券 200 → 净价 2800、国补后 2380；挂牌 6500、券 100 → 净价 6400、国补后 5900。历史 49 个日期原值保留；公式用于新采价日期，若要全历史重算需另立可追溯的重算批次。

券价核验：`delta = list_price - api_coupon_amount - api_actual_price`。统一按分比较，差异超过 1 分标记 `PRICE_COMPONENT_MISMATCH`，正负差值都展示。绝不把 `originalPrice - actualPrice` 自动写成优惠券，因为价差可能包含其他优惠、补贴、会员条件或错误匹配。人工可以确认真实挂牌/券额，也可保留原券额并注明“价差来自非券优惠”；记录理由和证据后才解除发布阻断，不要求为了凑相等而修改券额。

来源限制沿用 14 家店铺全名：华为京东自营旗舰店、荣耀京东自营旗舰店、小米京东自营旗舰店、OPPO京东自营旗舰店、一加手机京东自营旗舰店、真我realme京东自营旗舰店、vivo京东自营旗舰店、iQOO京东自营旗舰店、三星京东自营官方旗舰店、魅族京东自营旗舰店、联想moto手机京东自营旗舰店、努比亚京东自营旗舰店、红魔京东自营旗舰店、中兴京东自营旗舰店。

每日按型号+存储生成关键词，先重新查询搜索结果，再获取候选详情；已核验商品绑定只作优先匹配与变更检查，不能以昨日详情替代今日搜索。型号、RAM、ROM、特殊版本、京东自营和指定店铺均精确验证。二手、合约、套餐、配件及规格不清的候选拒绝进入自动生效；拒绝原因可追溯。颜色不是当前 SKU 主键，但所选颜色必须留证据。

首版选品沿用来源表逻辑：合格同规格候选按 actualPrice、挂牌价顺序取较低者，保留备选。后续若低价候选切换为不同商品/颜色，记录 `SOURCE_CHANGED` 并核验，防止来源切换制造假波动。接口价差异常仍需要拦截，不能因“最低”而放行。

| 触发情况 | 单元格/行状态 | 工作室动作与生效规则 |
| --- | --- | --- |
| 店铺/型号/规格不匹配 | 匹配失败，价格不填 | 打开搜索，选择合格商品并复核详情 |
| 没搜索到合格结果 | 未匹配，价格空白 | 进入商品/店内搜索确认；不等于下架 |
| 超时/限流/接口异常 | 采集失败 | 系统退避重试；不要求工作室判断停售 |
| 必填金额缺失或非法 | 对应单元格标缺失/非法 | 补充正确值和来源后重算 |
| 实际价与挂牌减券不符 | 优惠券格和行显示差额 | 点击具体商品核验，修改券额或说明其他优惠 |
| 券过期、未开始、单件不达门槛 | 券条件异常 | 核验可用券；记录必要条件 |
| 详情不足以确认规格、无货/在售不明 | 待核验 | 核对商品版本与供货状态 |
| 相比上一生效日波动超过配置阈值 | 价格波动待核验 | 核对促销/型号/版本；初版暂建议 20%，上线前可调 |
| 全部校验通过 | API 校验通过 | 自动创建生效价格版本；不标为人工已核验 |
| 人工核验完成 | 人工已核验 | 保存证据与结论，发布版本；重试不得覆盖 |

工作室点击“核验”后：领取 → 打开真实商品链接 → 对照型号与存储 → 确认价格/券额/券条件 → 填写证据链接或截图 → 保存并确认。确认在售但无优惠券可填显式 0；确认无货、停售、未上市是不同业务状态，不能统一填 0。字段未知与不适用均保留 null，并配状态码。

每条记录同时提供：

- **查看商品**：API 实际返回的购买链接，支持当前 u.jd.com 链接；若有经核验的商品直链也保存，不能把 opaque goodsId 或未确认的 spuid 生造为京东 SKU 链接。
- **重新搜索**：保存并展示原始查询词与京东搜索链接，按型号+存储 URL 编码构造。接口没匹配结果时仍可点开搜索。
- **采集详情**：本系统采集记录详情页，展示请求日期、参数（脱敏）、详情响应与候选；尚待开发，不把计划路由冒充已有链接。

## 七、多人编辑与并发保存

- 使用实名可区分的内部账号，管理员/编辑核验人员/只读角色；工作室按需看采价与维度，不能接触接口凭证。对历史原始写入口、导出、导入、采价触发、维度修改一起补上鉴权，不能仅隐藏按钮。
- 挂牌、券额可编辑，国补后只读。人工编辑保存为字段级覆盖，并显示“保存中/已保存/失败”；批量粘贴在服务端按 SKU+日期+字段提交，不再传整表覆盖。
- 每字段保存附带基础版本；事务中比较版本再写入。A 改挂牌、B 改同条记录的券额可以安全合并，后端基于合并值统一重算国补并推进记录版本；两人同时改同一字段则返回 409，展示服务端值、自己的值和操作者，让用户明确选择。
- 核验确认/发布采用记录级版本，防止发布时遗漏刚发生的字段修改；重新查询返回的结果也必须检查 observation 与人工覆盖版本。
- 行级领取与短期编辑占用用于提示“某人正在核验”，带心跳、到期时间和管理员释放；真正防覆盖依赖数据库版本，不依赖 UI 锁。
- 服务端事件（SSE）广播已保存数据和任务进度，前端按版本刷新；离线期间显示未保存草稿，重连先检查版本再重放，不以旧缓存覆盖服务端。
- API 候选与人工确认值分开。重复采价只产生新的 observation；当天已有人工确认时显示“有新接口结果待比较”，不自动覆盖。更正生效值记录新 revision，不改写旧证据。
- 先保存、校验、确认，再发布。接口自动通过也走同一个服务端发布事务。编辑未发布值时，分析仍指向此前生效 revision，并明确显示有待发布修改。

## 八、数据生效、兼容和分析

每日工作记录可为空/待核验；正式分析只读每个 SKU+日期的生效 revision。异常项不发布；同一天其他通过项允许生效，页面同步显示“今日应采/已采/已生效/待核验/缺失”和各品牌覆盖率，避免把样本变动误读为整体价格变化。

趋势只能基于真实观测/已发布价格；缺失为 null，不当作 0、不自动制造涨跌。若某些页面展示“最近一次有效价”，必须同时显示其原始日期与“非当日价”，不能伪装成今日采价。均值与环比明确有效样本数量；需要可比环比时取相邻日期都有有效值的 SKU，新增/停售单独统计。确认停售记录状态事件，不造 0 元价格。

迁移采用新表做唯一权威写源，由兼容适配层生成旧页面需要的 `{dates, rows, snapshots}` 结构，保持 listPrice/coupon/finalPrice/biPrice 字段契约。读接口可暂留兼容；旧整表写入口在切换后必须关闭或转成带权限与版本检查的字段写入，防止双源。

Excel 改为导入/导出与兼容产物，不再与新数据库双向自动覆盖。DuckDB 从生效价格、维度和其他现有业务源构建；刷新按批次去抖，不能每个键盘输入都重建。可靠 outbox/刷新任务记录与生效事务一起落库，刷新失败重试并提示，不能只发一个内存事件就算完成。既有 49 个历史日期与数据库快照保留，先只迁移存储表示，不重算业务事实。

## 九、任务、调度与日志

- 调度在云端服务内执行，而不是依赖本机 Chrome 或 Codex 对话。持久化任务表保存北京时间每天 10:00 的槽位；唯一键防重、租约防多个进程重复执行，重启后补领当天未完成任务，不无限补跑历史日期。
- 一日同一 SKU 可多次查询，每次保留 observation；只有一个当前生效版本指针。搜索任务可按型号和规范查询词复用，以减少重复请求，仍保留每个存储版本自己的匹配结果。
- 初版并发限 4，可配置；超时、429 和暂时性故障做有上限退避重试，业务无匹配保留结果，不反复轰炸。到达重试上限后形成明确失败列表，支持手动重试。
- 四类日志：任务运行日志、API 原始响应与候选日志、字段操作审计、核验/发布/撤销日志。统一关联 run_id、sku_id、业务日期、用户、request_id、响应摘要/哈希、规则版本；记录失败请求与拒绝候选的原因。
- 价格与人工操作审计建议长期保存，原始响应首版建议在线保留 180 天后压缩归档；截图/证明与价格版本关联，不依赖短链长期有效。具体保留期为实施默认建议，不代表已建立归档任务。
- API 令牌、Cookie 与授权头必须脱敏，接口密钥仅服务端保存。应用账户不具有修改审计日志的业务入口，数据库备份需覆盖新表与原始响应归档索引。
- 原始响应与日志归档至同目录 `.archive` 或明确备份目录，不使用 rm/rmdir/dd/shred，不在发布脚本清理业务文件。

## 十、实施顺序与每步验收

| 阶段 | 工作 | 进入下一步的验收条件 |
| --- | --- | --- |
| 1. 冻结规则与导入预览 | 再读生产快照、别名/品牌映射预览、逐行导入计划、公式样例与权限清单 | 重合/新增可追溯；重复导入零新增；特殊版不混；原历史与 PPV 不变；定位缺失可见 |
| 2. 数据底座与账号 | 新表、历史只读迁移、字段 PATCH 与版本冲突、身份鉴权、审计事务 | A/B 不同字段不丢失；同字段 409；旧页面不能整表覆盖；无权限不能写；发布与日志原子性通过 |
| 3. 每日采价工作台 | 日期单选、型号/存储主键、价格编辑、只读公式、维度子 tab、首批 10.27 导入 | 394 条逐行对上文件；183 新项与 211 复用预估经复核；116 未匹配留空；143 差异被标识；旧 75 项无假数据 |
| 4. API 与核验闭环 | 服务端搜索/详情适配、14 店限制、候选证据、核验领取/保存/确认、任务重试 | 错型号/容量/店铺不发布；actualPrice 异常不自动改券；真实商品/搜索链接可用；人工值不被采价重试覆盖 |
| 5. 分析兼容 | 统一生效视图、旧数据适配、Excel 输出公式、数仓刷新队列、完整率提示 | 新旧数据抽样核对；缺失不当 0；新样本与旧样本分清；概览/汇总/风险/专家数字可追溯到生效版本 |
| 6. 10:00 自动运行与上线 | 先手动真实批次验收，再启用每日任务；两个核验账号同时操作演练 | 服务重启不重跑、不漏任务；失败可重试；历史保留；可回滚到旧代码与只读原库快照 |

先在克隆的生产数据与独立测试实例验证；旧原始数据库保持备份可读。正式切换时暂停旧写入，做最终增量迁移与核对，短暂切换后只开放新入口。回滚时必须保留切换后新增的编辑/核验/价格版本并生成增量导出，不能直接恢复旧库覆盖用户刚完成的工作。

稳定后再考虑定制复杂实时协作、更多平台或自动 OCR；首版交付重点是准确匹配、公式一致、异常闭环、多人不互相覆盖、每个数字有来源。

## 待实施阶段核实的边界

- 云端接口鉴权与额度、商品详情返回是否稳定、访问链接能否打开；本方案没有新增 API 查询或宣称报价是结算价。
- 来源表里的 N/N-1 是相对代际，先按导入时的 2026-10-27 基准保存；以后更新需有生效日期，不能所有型号同一天自动减一。系列的“最新代”基准要由型号配置维护。
- 新型号机型定位、PPV/BI 映射需要有依据后补齐；缺失不阻止建档，但对应维度统计归“待配置”，风险分析标“未匹配BI”，不生成假的分类或价格。
- 多人账号的姓名、具体分工、上传证据可见范围、保留期可在实施账号阶段确认；不影响先完成数据底座。

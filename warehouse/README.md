# 3C行业专家轻量数仓

## 建仓目标

数仓位于 `data/warehouse/gtm_warehouse.duckdb`。现有 Excel、SQLite 和 DailyPrice
仍是业务数据源，数仓只作为统一分析层，不反向修改原始数据。

刷新与校验：

```bash
npm run warehouse:build
npm run warehouse:verify
```

## 基础事实表

| 表 | 最细颗粒度 | 主要度量 |
| --- | --- | --- |
| `fact_new_sku_price_daily` | 标准SKU＋日期 | 新机发售价、国补后价格试算、挂牌价、优惠券 |
| `fact_brand_market_weekly` | 市场对象＋周 | 品牌周度份额、大盘指数 |
| `fact_new_product_sales_weekly` | 型号或系列＋周 | 分周销量、累计销量 |
| `fact_used_s_grade_price_daily` | PPV＋日期 | BI出货价 |

公共维表为 `dim_brand`、`dim_product`、`dim_sku`、`dim_grade`。
`bridge_ppv_sku_mapping`负责记录PPV与标准SKU之间的唯一匹配或映射冲突。

## Agent业务表

| 中文业务视图 | 颗粒度 | 用途 |
| --- | --- | --- |
| `新机价格走势表` | 标准SKU＋监测日期 | 原始价格、聚合有效价格和沿用来源 |
| `新机价格走势聚合表` | 样本范围＋聚合维度＋日期 | 与当前【概览】一致的均价和环比 |
| `新旧机风险表` | 标准SKU＋新机价格日期 | 新旧机价格对比与四个风险指标 |
| `市场销量趋势表` | 型号或系列＋周 | 新品周销、品牌份额和大盘指数 |

## 固定指标口径

| 指标 | 公式 |
| --- | --- |
| 高收价差 | BI出货价－国补后价格试算 |
| 高收风险率 | BI出货价÷国补后价格试算 |
| 旧机残值率 | BI出货价÷新机发售价 |
| 新机残值率 | 国补后价格试算÷新机发售价 |

国补后价格试算已经包含优惠券，计算时不再重复扣减优惠券。

## 新机价格聚合

- 价格大于0时使用当日实际价格。
- 空值、0和“已下架”统一沿用此前最近一次有效价格。
- 从未出现有效价格的SKU不进入该日期聚合。
- 最新监测日期仍无有效价格的SKU不进入概览聚合样本。
- 发布均价和国补后均价均为SKU算术平均值，不按销量加权。
- 品牌环比为各SKU环比率的算术平均值。
- 聚合样本支持全量、老样本和5.26新增。

## 刷新策略

- API服务启动时会先刷新一次数仓；运行期间默认每15分钟刷新一次。
- 新机价格草稿、市场趋势、新品周销发生写入后，会立即触发一次后台刷新。
- 可通过 `WAREHOUSE_REFRESH_ENABLED` 和 `WAREHOUSE_REFRESH_INTERVAL_MINUTES`
  控制是否启用及刷新间隔；同一时刻只运行一个刷新任务。
- 新机售价、市场趋势和新品周销是完整源，每次刷新全量重建对应事实表。
- DailyPrice当前文件只保存最新快照。数仓按数据日期增量写入S等级事实表，
  同一天重跑会覆盖当天快照，不会删除已积累的其他日期。
- 新旧机风险使用不晚于新机价格日期的最近一次BI价格，并分别保留两个数据日期。
- 数据源路径和年份可通过 `.env` 中的数仓变量覆盖。

## 当前数据限制

- DailyPrice本地源当前只有一个日期的快照，数仓会从后续刷新开始积累历史。
- PPV映射冲突不会由脚本自行选择SKU；冲突记录保留在映射桥表并从风险计算中排除。
